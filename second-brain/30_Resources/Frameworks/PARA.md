# PARA: Projects, Areas, Resources, Archives

Source: Tiago Forte, Forte Labs. Summarised from
https://fortelabs.com/blog/para/ and *The PARA Method* (2023). Paraphrased,
not copied.

## The four categories

| Folder | Definition | Test | Examples for Brad |
|---|---|---|---|
| `10_Projects` | Short-term efforts with a goal and an end date | "Can I say what *done* looks like and roughly when?" | NEXUS Play Store launch, Google account consolidation, 50-Year Anniversary video, Fibreglass cage video, Toop driveway plans |
| `20_Areas` | Ongoing responsibilities with a standard to maintain, no end date | "Will I still be responsible for this in a year?" | Health, Hydralada Marketing, Toop Street property, Morley Studio, Finance, Spirituality, Relationships, IT and Devices |
| `30_Resources` | Topics of interest and reference material | "Is this useful but not tied to a commitment?" | Prompts, frameworks, architecture inspiration, manufacturing innovation, branding references, supplements research |
| `40_Archives` | Anything inactive from the other three | "Have I touched this in 60 days? Is the project finished?" | Completed videos, old campaigns, past wishlists |

`00_Inbox` sits in front of PARA as the single capture point. Nothing lives
there longer than one weekly review.

## Filing rules (Forte's "organise by actionability")

1. **Projects first.** Ask "which active project needs this?" before anything
   else. Put it there even if it also fits an Area.
2. **Then Areas.** If no project needs it, ask which area of responsibility it
   serves.
3. **Then Resources.** If it serves no responsibility, it is a reference or an
   interest.
4. **Otherwise Archive.** If it serves nothing right now, archive it. Archiving
   is reversible, deleting is not.
5. **Few folders, shallow tree.** Four top-level folders, one level of
   subfolders for individual projects, areas or topics. Avoid a third level
   unless a project genuinely needs it.
6. **Same structure everywhere.** The same four folders and the same names in
   Dropbox, OneDrive, NAS, Notion, Todoist, bookmarks, YouTube playlists,
   Remarkable, Reflect, email folders. Numbered prefixes keep the order fixed.
7. **Move things freely.** Information flows between the four categories as
   its actionability changes. A resource becomes a project folder when you
   commit to it. A finished project moves to archive, and its notes can be
   mined later.
8. **Projects need a goal.** Every project folder gets a one-line outcome and
   a target date in its README. If you cannot write that line, it is an area
   or a someday idea, not a project.
9. **Keep the project list short.** Forte suggests 10 to 15 active projects at
   most. Everything else is paused (archive with a `paused-` prefix) or is
   really an area.

## Numbering convention used in this repo

```
00_Inbox
10_Projects/<YYYY-MM>_<short-name>/
20_Areas/<Area-Name>/
30_Resources/<Topic>/
40_Archives/<YYYY>_<original-folder-name>/
```

Date prefixes on projects let you sort by when they started and see what is
stale. Archives keep the original name so search still finds them.

## Reviews that keep PARA alive

- **Weekly**: empty `00_Inbox`, file to PARA, check each project still has a
  next action. See `routines/weekly-review.md`.
- **Monthly**: re-read the project list, close or pause anything stalled,
  promote any resource that has become a commitment.
- **Quarterly**: sweep `10_Projects` and `20_Areas` for untouched folders and
  move them to `40_Archives`.
